Snap a civic problem. AI agents file it and follow it up.

Nagrik is an Android app for Indian towns. Photograph a pothole, broken streetlight, garbage dump or blocked drain: agents work out which municipal office is responsible, write a formal complaint, file it on the grievance portal with a headless browser, check on it, and draft an escalation when nothing happens.

▶ Open the live demo How it works

No sign-up and nothing to install: you get your own sample account with four complaints. Everything goes to a practice copy of the municipal portal, never to a real office, and the account is deleted after 24 hours. The first load can take up to a minute while the free server wakes up.

What to try in the demo

The sample account opens with complaints at every stage, so you can see the whole life of a complaint in a few minutes.

  1. File the drainage complaintIt's marked "Ready to file". Tap Submit and the Submission agent opens the portal in a headless browser, fills the form with the photo, and captures the grievance number.
  2. Approve an escalationThe street light complaint got no response for 14 days, so the Monitoring agent drafted a letter to the Municipal Commissioner. Read it, edit it, and send it.
  3. Check a statusOn the pothole complaint, tap "Check status now". The agent reads the live status from the portal and adds it to the timeline.
  4. Report a new problemTap Report and pick one of the sample photos (or upload your own). Watch the agents classify it, route it and write the letter.

Also worth a look: switch the language to Telugu or Hindi on the welcome screen, ask the Help assistant a question, and open the agent activity timeline on any complaint.

How the AI works

A coordinator runs five specialised agents. Each is a tool-calling loop (Vercel AI SDK + Google Gemini) where the model picks its next action. Every tool call is logged.

IntakeReads the photo: issue type, severity, address. Spots the same problem already reported nearby.
JurisdictionFinds the responsible office in a verified directory, or proposes one from official .gov.in sources for admin review.
DraftingWrites a formal letter in the format that office expects, without inventing facts.
SubmissionFiles on the portal with Playwright and captures the reference number. Stops at any CAPTCHA or OTP.
MonitoringA daily job checks status on the portal and drafts an escalation when nothing moves.
🛡️ Safety rules live in the code, not in the prompt. A model can't talk its way around them.
  • No email without approval. Agents can only save escalation drafts. Sending needs the citizen to approve that exact text.
  • No invented offices. New departments need an official government source and stay pending until an admin approves them.
  • No fake filings. A complaint is recorded as filed only if a form was really submitted in that run.
  • CAPTCHAs are never bypassed. The complaint is handed back to the citizen with the letter ready to paste.
  • Prompt injection is treated as data. Instructions hidden in a note or address are stripped, and the tool checks hold even if a model is fooled.
  • Real portals need the citizen's tap. Auto-filing only happens on portals the citizen has confirmed.

Tested, not trusted

GitHub Actions runs the failure-mode tests and an agent evaluation on every push, and the build fails if any check fails or the eval scores drop. The AWS deploy only ships a build that passed.
